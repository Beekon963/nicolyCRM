## Phase 3: お金 — 完了

お金の画面・設定は**すべてオーナーだけ**（管理者には出さない・データも取らない）。計算は `src/lib/money` の1か所にまとめ、要件 §10 の計算テストケース8件をすべてテストに入れる。

| 区切り | 内容 | 終わったら確認できること |
|---|---|---|
| 3-1 計算 | `src/lib/money`: 単価の選び方（現場の上書き → 取引先×会場 → 取引先）、請求（人日・現場固定・成果・交通費、消費税）、支払い（日当・インセンティブ・調整・交通費経費・源泉・差引）、見込み、粗利 | 計算テストケース8件が通る |
| 3-2 単価・設定の画面 | 取引先の「請求設定・標準単価」（会場ごとの標準も）、現場の「この現場の単価」（上書き・インセンティブの上書き・日当の上書き）、設定の「インセンティブ単価」「税・源泉」「支払日」「月次目標」 | 単価を入れると、その月の請求・支払いの見込みが出る |
| 3-3 お金の画面 | 今月の売上・支払・粗利（確定分と見込み分）、目標との比較、12か月の推移、取引先別・会場別。請求（取引先別＋現場ごとの明細）、支払い（スタッフ別＋明細・インボイス登録の有無・調整額・支払済）。ホームの「今月の数字」 | 月の請求額・支払額・粗利が一目で分かる |
| 3-4 月次締め | チェックリスト（未確定の実績・未承認の経費・未報告）→ 締める（請求・支払いを保存し、その月を変更できなくする）→ ロック解除（理由）→ もう一度締める | 締めた月は直せず、解除すると直せる |
| 3-5 出力 | 請求集計 CSV・支払明細 CSV（Excel で文字化けしない）、freee の「取引のインポート」用 CSV（勘定科目などは設定で変えられる）、全銀フォーマットの総合振込データ | Excel・freee・ネットバンキングに取り込める |

**決めたこと（2026-10-11）**
- 請求は**すべて月末締め**（1日〜末日）。取引先の締め日は使わない
- freee を使っている → freee の最新のヘルプで「取引のインポート」の形を確かめて作り、最後に一緒に取り込みを試す
- 全銀フォーマットの振込データを作る（振込元の口座・委託者コードはオーナーが設定画面で入れる。スタッフの口座には銀行・支店の番号が要る）
- 支払いは**翌月の決まった日**（日にちは設定で変えられる）

**作りながら決めたこと**
- 締めた月の画面は、締めたときに保存した金額（スナップショット）で出す。単価を後から変えても締めた月の数字は変わらない
- まだ終わっていない月は締められない（翌月1日から）。未処理があるときは一覧を出して確かめてから締める
- 締めた月は、実績・単価・経費・アサインに加えて現場（中止・日付など）も変更できない
- 支払いの状態: 未確定 → 確定（締めたとき）→ 支払済（支払日）。ロック解除で「確定」は「未確定」に戻る。もう一度締めても支払済みは残り、金額が変わった人を知らせる（差額は翌月の調整額で）
- freee: 請求は「収入」、報酬は「支出」の複数行（報酬・交通費経費・源泉の預り金をマイナス）。どちらも未決済。インボイス登録なしの人の税区分は、空なら発生日で自動（2026年9月まで 控80、10月から 控50）
- 振込データ: 締めた月・確定で未払い・差引1円以上の人だけ。口座の情報が足りない人は画面で名前を出して除く
- 全データの一括ダウンロード（要件 §7 バックアップ）を「書き出し」に入れた
- 稼働表の金額の列は「売上・報酬」（取引先の行は売上、スタッフの行は報酬）と、その月の売上・支払・粗利の1行

**お願いすること**: 支払日の日にち（初期値は翌月25日）、使っている銀行（ネットバンキング）の名前と委託者コード、源泉・税込/税抜・freee の税区分の扱い（税理士確認）、freee への取り込みを一緒に試す

**作りながら決めたこと**
- 日報の件数は、確定していれば確定件数、なければ速報。未報告の人は「（未報告）」と出す
- 日報のフォーマットはオーナーが作る（設定は管理者は不可、のルールどおり）。日報を作る・コピーするのは管理者もできる
- 書式の見本（NICOLY用・ラスタス用・NextWave用）はまだいただいていないので、NICOLY用だけ仮の書式で入れておき、ほかは設定画面で作ってもらう

- 研修の予約: 枠（日時・定員）を先に作り、空いている枠だけを出す形にした（TimeRex の「空き時間から自動で出す」の代わりに、Google カレンダーとつなぐと予定と重なる枠を出さない）。締切は始まる1時間前。予約用リンクは1つ（作る・止める・作り直すはオーナー、枠と予約は管理者も）。予約した人には控えの画面（参加の URL・カレンダーに追加・キャンセル）を出し、リンクを止めても控えは見られる。カレンダーの連携は任意（オーナーがカレンダー ID を入れたときだけ）
- シートとの連携: 管理用シートの月のタブを CRM から直接読んで取り込める（今までの CSV 取り込みと同じ確認画面）。シート → CRM は「取り込むときだけ」、CRM → シートは「CRM 〜」タブへの自動書き出し（同時に両方向に自動で合わせることはしない。食い違ったときにどちらが正しいか決められないため）

2026-10-11 のご要望（「案件が確定したらメンバーに勝手に通知が行くように」）。届け方は LINE 公式アカウント、受け取るのはスタッフ本人と社内（オーナー・管理者）、きっかけは「確定」「新しい現場」「前日」と決めていただいた。

| 区切り | 内容 | 終わったら確認できること |
|---|---|---|
| 5-1 LINE の自動のお知らせ | 自分の LINE をつなぐ（マイページ・CRM でコード → 公式アカウントに送る）。確定したら本人に確定連絡・社内に【確定】、新しい現場は社内に【新しい現場】、前日の決めた時刻に本人へ前日リマインド。送るお知らせのオン・オフ、送った記録 | スタッフが LINE とつなぎ、確定・前日のお知らせが LINE に届く |

**作りながら決めたこと**
- 新しい現場のお知らせは社内だけ（スタッフ全員に送ると通数が多く、募集は今までどおり打診で行うため）。まとめて作ったときは1通にまとめる
- 確定のお知らせは「打診中・補欠 → 確定」のときだけ。辞退・キャンセルから戻したとき・月の稼働表の取り込みでは送らない。入れてから1分たってから送る（間違えて確定して「元に戻す」を押したときに届かないように）
- 自分の操作のお知らせは自分には送らない。社内向けは LINE とつないだオーナー・管理者に送る
- 前日のお知らせは、決めた時刻（初めは18時ごろ）を過ぎてから、まだ送っていない人へ1回だけ。時刻より後に確定した人には、確定のお知らせのすぐあとに届く
- つながっていないスタッフには送らず、今までどおり画面の「LINEで送る」で送る（ホームの「確定連絡 未送信」に残る）

| 11-4 現場詳細 | 【案件詳細】の投稿（集合・入店・服装・持ち物）を、会場ごとに一番新しいものを会場のメモに入れる（稼働日程・稼働メンバー・電話番号の行は外す） | 会場のメモに集合場所などが入る |

**作りながら決めたこと**
- 記録のみの現場は `counts_only`（件数の記録だけ）。請求・報酬の計算には入れない（過去の請求・支払いはもう終わっているため）。報告も求めない
- 同じ日にその人の確定した稼働が別の会場にあれば、それに入れる（会場の書き方が CRM と違うとき）。打診中・キャンセルなど確定していないアサインがあれば入れない
- 件数のある行の下の、件数のない行（「PI1」の下の「D払い初回利用」）は、同じ名前か言いかえ表にあるときだけ数える（親と同じ人の分として1件）
- 名簿にいない人（他社のヘルパーなど）の件数は、その人の分として割ってから入れない（うちのスタッフの分を多くしない）
- ノート（[ノート]）は保存したトーク履歴に最初の100文字ほどしか入らないので使わない。「@All」で始まるお知らせは、例として件数が書いてあることがあるので報告として読まない
- 会場の書いてない報告は、同じ日に同じ人の報告で会場が1つに決まればそれを使う
- いただいたトーク履歴（実際のお名前・会場名・お客様のお名前）はリポジトリに入れず、読み取りの確かめはこの環境の中だけで行った。テストは仮の名前で行う。本番への取り込みはオーナーが画面から行う

## Phase 12: ランク制度に合わせる — 完了・公開済み（2026-10-13）

2026-10-12 にいただいた「ランク制度のご案内」（ランクごとの日当・1ランクごとの差）への対応。選んでいただいたもの: 日当は「ランクで決まる」、A＋ は「＋は半ランク分上がる」、P は「パートナー」、ほかの決まりは「遠方の上乗せ」「友達紹介のボーナス」「交通費は報酬に含む」「締切を毎月10日に」すべて。

| 区切り | 内容 | 終わったら確認できること |
|---|---|---|
| 12-1 日当はランクで決まる | 日当 ＝ 現場ごとの日当 → 人ごとの日当（決まった額と違う人だけ）→ ランクの基準日当。スタッフの登録・取り込みでランクの額を写さない（空ならランクに合わせて変わる）。スタッフ詳細に「ランク A の基準日当 〇〇円」のように出す。ランク「P（パートナー）」を足す（日当は人ごと） | ランクを上げると、その人の日当が変わる |
| 12-2 遠方の上乗せ | 現場の人の「…」から「最寄り駅からの時間」（1時間30分まで／〜2時間／〜2時間30分…）を選ぶ。1時間30分を超える30分ごとに、日当に上乗せ（1回分の額はお金の設定で決める）。管理者も選べる（金額は見えない） | 〜2時間を選ぶと、その人の日当が 1回分増える |
| 12-3 友達紹介のボーナス | スタッフに「紹介してくれた人」を入れる。紹介された人が決めた回数（初期値 5回）稼働したら、お金 → 支払いに出て、「この月の調整額に足す」でボーナス（額はお金の設定）を紹介した人の報酬に足す。足したものは調整額として残り、消せば元に戻る | 5回稼働した人の紹介者に、ボーナスを1回だけ足せる |
| 12-4 交通費は報酬に含む | 設定（締切・会社情報）に「日当は交通費込み」（初期値オン）。オンのあいだ、マイページの報告に交通費の欄を出さない（送られても入れない）。その他の経費はこれまでどおり | マイページの報告に交通費の欄が出ない |
| 12-5 締切を毎月10日に | 稼働可能日の提出締切の初期値を 10日に。本番は今が 20日のままなら 10日に変える（ほかの日に変えていれば変えない） | 設定とマイページの締切が 10日になる |

**決めたこと**
- 金額（ランクの基準日当・遠方の1回分・紹介のボーナス）はリポジトリに入れず、オーナーが設定画面で入れる（今までと同じ）
- ランクを変えると、締めていない月の日当も新しいランクで計算される（人ごとの日当を変えたときと同じ）。月の途中でランクを変えるときは、前の分を締めてから変えるか、現場ごとの日当で直す
- 遠方の上乗せは日当に足す（源泉の対象。請求には入れない）。移動時間は人と現場ごとに選ぶ（自動では測らない）
- ランク P（パートナー）は一番下に足した（並び順は 設定 → ランク で変えられる）
- 友達紹介のボーナスは自動では足さず、支払いの画面に出して、オーナーが「足す」を押す（すでに外で払った人に二重に払わないため）。紹介された人の稼働は、確定・中止でない・今日までの日を数える（LINE から取り込んだ記録のみの現場も数える）
- 日当は交通費込みでも、管理者の交通費・経費の承認の画面は残す（その他の経費と、前に出された交通費のため）

## Phase 15: 画面テストの安定化 — いまここ

2026-10-13 のご要望「画面テストの安定化」（まとめて流したときに、ときどき失敗するテストを直す。画面と動きは変えない）。

| 区切り | 内容 | 終わったら確認できること |
|---|---|---|
| 15-1 原因を探す | データを消さずに全部を3回続けて流し、失敗したテストの記録（画面の写し・通信）から原因を調べた | 失敗の原因が分かる |
| 15-2 直す | ①予定・報告・稼働可能日を入れる人を、テストごとに作って終わったら消す（13のテストファイル。ダミーデータの人をくじ引きで選ぶと、同時に動くテストと同じ人を取り合う）②書式を付ける取引先もテストごとに作る ③一覧の並びは、行が出そろってから読む ④開いてすぐ入力する画面は、読み込みが落ち着いてから操作する ⑤マイページのテストで作った現場を消す | 全部を続けて何回流しても通る |
| 15-3 稼働表の直し（アプリ） | 稼働表で選んだマスを「上から何行目か」ではなく「どの人・どの取引先の行か」で覚える。1 2 3 で続けて入れている途中に表が新しくなり、ほかの人が登録・削除されて行がずれても、同じ人のマスに入り続ける | 入力中にスタッフが増えても、ほかの人のマスに入らない |

**分かった原因**
- 打診の候補の並び順のテストが、一覧が出る前に読みに行っていた（だれも見つからず失敗）
- 13のテストファイルが、ダミーデータのスタッフ約35人からくじ引きで人を選んでいた。2つのテストが同じ人を選ぶと、同じ日の予定・稼働可能日・報告が混ざる
- 「稼働開始の報告」「日報」のテストが、みんなが使う取引先に書式を付けていた
- 単価・実績確認の画面で、開いた直後に入力・クリックすると、まれにブラウザーが止まったまま待ち時間（30秒）を使い切った
- 先の日付をくじ引きする幅が狭く（120〜300日後）、2つのテストが同じ日を選ぶと、稼働表の日ごとのリストに相手の現場が割り込んだ → 120〜1500日後の、まだ現場のない日から選ぶ
- 単価のテストが、ダミーデータの人の日当を書きかえたまま戻していなかった → テスト専用の人を使う
- 稼働表で 1 2 3 と続けて入れると、保存のあとに表が新しくなったとき、行がずれていると次のキーが隣の人のマスに入った（テストで人を作る・消すようにして見つかった。本番でも、入力中にだれかがスタッフを登録すると起こりうる）→ 15-3 で直した
