# NICOLY 社内CRM 要件定義（Claude Code 実装用）

作成日: 2026-10-06 ／ 依頼者: 森部 太陽（NICOLY 代表）
このファイルは、オーナーへのヒアリング結果をもとにした要件定義です。Claude Code はこれを読んで設計・実装・テストまで進めてください。

> リポジトリ保存時の注記: 原本は `NICOLY_CRM_要件定義.md`。Phase 0 の確認で決まった変更点は `docs/phase0-questions.md` に記録し、ここには原文をそのまま残す。

## 0. Claude Code へ（最初に必ず読むこと）

- **役割**: この要件定義をもとに、NICOLY の社内CRMを設計・実装・テストし、デプロイ手順と操作マニュアルまで用意する。
- **最優先は「現場で毎日使われること」**。機能の多さより、少ないタップで迷わず使えることを優先する。依頼者は「作ったけど使いにくくて使わない」状態をいちばん嫌っている。
- **進め方は §12 のフェーズ順**。各フェーズの最初に計画を示し、最後にテスト結果と「ユーザーが自分で確認する手順」を出して、承認を待ってから次へ進む。
- **曖昧な点・要件同士の矛盾は推測で埋めずに質問する**。ただし細かいUIの判断は §9 の原則に沿って自分で決めてよい。
- **§13「仮置きの前提」は Phase 0 でまとめて確認する**。
- **要件にない機能を勝手に足さない**。良いアイデアは「提案」として別に出す。
- **ユーザーへの説明は日本語**、専門用語は最小限。ユーザーがコマンドを打つ必要があるときは、コピペで済む形で示す（ユーザーは Claude Code でアプリを作って公開した経験あり）。
- Phase 0 で、§11「開発ルール」を `CLAUDE.md` として保存する。

## 1. 事業の前提

- **会社**: NICOLY。docomo 関連の携帯催事（商業施設・店舗でのイベント販売）業務を取引先から業務委託で受け、個人事業主（クローザー等）へ業務委託で再委託している。
- **規模**: 月 50〜150 現場、稼働する個人事業主 30〜80 人。
- **現状の管理**: Google スプレッドシート ＋ LINE のトーク・グループ。
- **解決したい困りごと（すべて）**
  1. 取引先・協力会社への連絡・追客の取りこぼし（いつ誰と何を話したか、次に何をするかが抜ける）
  2. 情報が散らばって探せない（連絡先・条件・契約などがあちこちにある）
  3. 実績・売上・支払いの集計が手作業
  4. 誰をどの現場に出すかが混乱（稼働可能日の集め方も人によってバラバラ）
- **業務委託であること**: 画面上の用語は、雇用を連想させる言葉（シフト・出勤・勤怠・給与 など）を避け、§2 の用語を使う。
- **利用開始の目標**: 1〜2か月以内。まず第1弾（現場・アサイン・実績）を先に使い始める。

## 2. 用語集（画面表示もこの言葉にそろえる）

| 用語 | 意味 |
|---|---|
| 現場 | 1日 × 1会場の稼働単位。複数日開催は日ごとに1現場（一括作成できる） |
| 取引先 | 案件を発注してくれる会社。請求先 |
| 協力会社 | 提携・開拓の対象となるクローザー会社など。人の手配には使わない |
| 会場 | 催事を行う店舗・商業施設 |
| スタッフ | 再委託先の個人事業主 |
| 役割 | クローザー / キャッチャー / ディレクター など（設定で編集可） |
| 打診 | スタッフへの参加依頼 |
| 確定 | その現場への参加が決まった状態 |
| 獲得 | 契約の獲得。獲得項目ごとに件数を数える |
| 速報 | スタッフが稼働日に報告する件数 |
| 確定実績 | キャンセル・否認などを反映して自社で確定した件数。請求・支払いはこれで計算する |
| 報酬 | スタッフへの支払い（「給与」と呼ばない） |
| 稼働 | 現場での業務（「出勤」「シフト」「勤怠」と呼ばない） |
| 稼働可能日 | スタッフが稼働できる日（○ / △ / ×） |
| 稼働履歴メモ | 直前キャンセル・遅延・トラブル・良かった点などの記録 |
| マイページ | スタッフ専用のログイン不要ページ（§4.5） |

## 3. 利用者と権限

| | オーナー（太陽） | 管理者（数名） | スタッフ |
|---|---|---|---|
| ログイン | あり | あり | なし（専用マイページURL） |
| 現場・アサイン・実績 | すべて | すべて | 自分の分のみ |
| スタッフ情報（金額以外） | すべて | すべて | 自分の予定・実績のみ |
| 取引先・協力会社（営業・追客） | すべて | すべて | なし |
| **金額情報**（請求単価・日当・インセンティブ単価・支払額・売上・粗利・振込口座・源泉・インボイス・契約書） | すべて | **一切見えない** | なし |
| 交通費・経費の申請 | 承認可 | 承認可（申請額のみ見える） | 自分の分を申請 |
| 設定・ユーザー招待・月次締め・ロック解除 | 可 | 不可 | — |

- 「見えない」は画面で隠すだけでなく、**DB（RLS）と API のレベルで取得できない**こと。金額系は専用テーブルに分離し、RLS で守る。
- アカウントは**招待制**（一般の新規登録は不可）。ログインは Google アカウント または メールのマジックリンク。
- 管理者を無効化したら即ログイン不可になること。

## 4. 機能要件

### 4.1 ホーム（ログイン直後の画面）

カードを縦に並べ、各項目をタップすると該当画面へ飛ぶ。

1. **今日・明日の現場**: 現場ごとに「必要人数 / 確定人数」。欠員は赤。打診への未回答者、実績の未報告者も表示。
2. **要対応**
   - 直近7日以内で欠員のある現場
   - 未回答の打診（24時間以上経過は強調）
   - 実績の未報告（稼働日を過ぎたもの）
   - 未承認の交通費・経費
   - 明日の現場で前日リマインドを送っていないもの
   - 翌月分の稼働可能日の未提出者（締切日以降は強調）
3. **今日やること（営業）**: 次回アクション日が今日以前の取引先・協力会社（期限切れは赤）
4. **今月の数字（オーナーのみ）**: 売上・支払・粗利を「確定分」と「見込み分」に分けて表示、月次目標との比較
5. **実績**: 今月のスタッフ別・会場別・取引先別の獲得件数トップ（確定ベース／速報ベース切替）

管理者のホームには 4 を表示しない（データ自体を取得しない）。

### 4.2 現場

- **一覧**: 日付リスト（初期表示は今日から2週間）と月カレンダーを切替。フィルタ: 取引先 / 会場 / 欠員あり / ステータス。日本の祝日を表示。
- **作成**: 取引先、会場、日付、開始・終了時刻、集合時刻、集合場所、役割別の必要人数、服装・持ち物・注意事項。
- **一括作成**: 期間＋曜日指定（例: 10/1〜10/31 の土日）で、日ごとの現場をまとめて作成。同じ「グループ」として紐付け、グループ単位でも一覧できる。
- **複製**: 既存の現場を別日にコピー。
- **ステータス**: 予定 → 人員確定（必要人数を満たしたら自動）→ 実施済（日付経過で自動）→ 実績確定 → 締め済。別に「中止」。
- **単価の上書き（オーナーのみ）**: 取引先の標準単価をこの現場だけ変えられる（§4.9）。
- 現場詳細から、会場情報（住所・地図リンク・最寄り駅・入館方法・控室など）を参照できる。

### 4.3 アサイン（誰をどの現場に出すか）

**候補を探す**（現場詳細のボタン）でスタッフを以下の情報つきで一覧表示する。

- その日の稼働可能日（○ / △ / × / 未提出）
- ダブルブッキング（同日に別現場で打診中・確定）→ 警告
- NG（この会場 / この取引先がNG）→ 警告（選択はできるが確認を挟む）
- 役割、ランク、直近3か月の平均獲得件数（確定ベース）
- 最寄り駅・対応エリア（会場のエリアと一致すれば印をつける）
- 稼働履歴メモのうち注意事項の回数（直近6か月の直前キャンセル・遅延など）

**並び順**: ○ → △ → 未提出 → ×・NG・ダブルブッキングの順。同じ順位の中ではランク → 平均獲得件数の高い順。

**打診の流れ**

1. 候補から複数人を選んで一括で「打診」→ 状態は「打診中」。
2. テンプレートから文面を自動生成（現場名・日時・会場・役割・マイページURL）。
3. **「LINEで送る」ボタン**（`https://line.me/R/share?text=` ＋ UTF-8 でパーセントエンコードした文面）でLINEアプリの送信先選択画面が開き、送り先を選ぶだけで送れる。**「コピー」ボタン**も並べる。
   - LINE のこの URL スキームは PC版LINE（Mac / Windows）では動かない（LINE公式ドキュメントより）。PC ではコピーを主ボタンにし、LINEで送るボタンは出さない。
4. スタッフはマイページで「参加できる / できない」を押す → 自動で「確定」/「辞退」になる。必要人数を超えた場合は「補欠」にして管理者に表示する。
5. LINEで口頭回答が来た場合のために、管理者が手動で状態を変えられる。

**状態**: 打診中 / 確定 / 補欠 / 辞退 / キャンセル（確定後に取りやめ）/ 当日不稼働（ドタキャンなど）

- 確定後は「確定連絡」文面（集合時刻・集合場所・持ち物・実績報告のお願い）を生成 → LINEで送る。
- 前日には「前日リマインド」文面を生成。送ったらチェックを付け、未送信はホームに出す。
- キャンセル・当日不稼働にするときは理由を選択し、スタッフの稼働履歴メモに自動で記録する。
- **欠員 = 役割別の必要人数 − 確定人数**。

### 4.4 スタッフ

- **一覧**: 検索（氏名・かな・電話番号）、フィルタ（役割・ランク・エリア・状態［稼働中 / 休止 / 終了］）。
- **詳細**
  - 基本情報: 氏名、かな、電話、LINE表示名、最寄り駅、対応エリア（複数）、役割（複数）、ランク、メモ
  - 稼働可能日カレンダー、今後の確定現場、過去の稼働と獲得実績（確定・速報）
  - NG設定（会場NG・取引先NG、理由）
  - 稼働履歴メモ（直前キャンセル・遅延・トラブル・良かった点）
  - **オーナーのみ**: 基本日当、源泉徴収の方式、インボイス登録番号（T＋13桁の形式チェック）、業務委託契約の締結日・契約書PDF、振込口座、支払履歴
- **マイページURL**: コピー / LINEで送る / 再発行（再発行すると古いURLは使えなくなる）。
- **マイナンバーは扱わない**（入力欄を作らない）。

### 4.5 スタッフ用マイページ（ログイン不要）

スタッフごとに専用URLを1つ発行する（推測できない長いランダム文字列）。**一度送ればずっと使える**ので、毎回リンクを送らなくてよい。ホーム画面に追加しやすいよう PWA 対応する。

スマホ前提、1画面1目的、大きなボタン。

1. **お願い**: 打診中の現場 → 「参加できる」「できない」
2. **予定**: 確定した現場（日時・会場・住所［地図リンク］・集合時刻と場所・持ち物）
3. **実績報告**: 稼働日当日〜7日後まで報告できる。
   - 獲得項目ごとに ＋ / − ボタンで件数入力
   - 一言コメント（任意）
   - 交通費（金額＋区間メモ）、その他の経費（任意）
   - 送信後も報告期限（稼働日の7日後）までは本人が修正できる。ただし管理者が確定したあとは修正不可（管理者に連絡）
4. **稼働可能日**: 月カレンダーで日をタップすると ○ → △ → × → 未入力 と切り替わる。メモ欄あり。今月の残りと翌月分を提出できる。
5. **過去の稼働**: 日付・会場・自分の獲得件数（確定 / 速報）

- 金額（日当・インセンティブ・支払額）は表示しない。
- セキュリティ: トークン検証、レート制限、URL再発行、`noindex`。サービスキーはサーバー側だけで使う。

### 4.6 稼働可能日の回収

- **全体向けの提出依頼文面**（「各自のマイページから○月分の稼働可能日を○日までに提出してください」）を生成 → スタッフのLINEグループに送る。個別リンクは不要。
- **提出状況画面**: 対象月の提出済み / 未提出の一覧。未提出者には個別リマインド文面（マイページURL付き）を「LINEで送る」で送れる。
- **代理入力**: 管理者がLINEで聞いた内容を入力できる（入力元［本人 / 管理者］を記録）。
- 締切日（初期値: 毎月20日に翌月分）は設定で変更できる。

### 4.7 実績（速報 → 確定）

- **速報**: マイページから本人が報告、または管理者が代理入力。
- **確定**: 実績確認画面で、現場ごと・スタッフごとに、速報件数が初期値として入った「確定件数」を編集して確定する。速報と差がある場合は理由（キャンセル / 否認 / 入力ミス / その他＋メモ）が必須。
- **一括確定**: 速報どおりでよい現場はまとめて確定できる。
- 確定後の修正もできるが、履歴（誰が・いつ・何から何に）を残す。月次締め後はオーナーがロックを解除しないと修正できない。
- **獲得項目（初期値）**: 「新規・MNP」「機種変更」「ドコモ光・home 5G」「dカード・でんき等の付帯」。設定で追加・名前変更・並び替え・無効化ができる（削除ではなく無効化にして、過去データを壊さない）。

### 4.8 取引先・協力会社（営業・追客）

- **一覧**: 種別タブ（取引先 / 協力会社）、ステータス別の表示（リスト / カンバン切替）、優先度、担当者。次回アクション日の順に並べ、期限切れは赤。
- **ステータス（6段階）**: 未接触 → 接触済み → 商談設定 → 商談済み → 取引中 → 見送り・休眠
- **「次回アクション日」と「次にやること」**は、取引中・見送り以外では必須（空のまま保存しようとしたら入力を促す）。未設定の会社は一覧で分かるようにする。
- **会社詳細**: 基本情報（住所・電話・Web・優先度・担当者・メモ）、担当者（複数）、活動履歴（時系列）、関連する現場（取引先の場合）、関連資料のリンク。
- **活動の記録はスマホで10秒**: 「記録する」→ 種類（架電 / LINE / メール / 訪問 / 商談 / その他）→ 結果（つながった / 不在 / 折り返し待ち / 資料送付 / アポ獲得 / 見送り）→ 一言メモ → 次回アクション日（ワンタップ候補: 明日 / 3日後 / 1週間後 / 日付指定）。
- 電話番号はタップで発信（`tel:` リンク）。
- **取引先の請求設定（オーナーのみ）**: 標準単価表（§4.9）、締め日、請求書送付先メモ、交通費を請求に含めるか。

### 4.9 お金（オーナーのみ）

#### 請求（取引先へ）

単価表は取引先ごとに「標準」を持ち、現場ごとに上書きできる。次の型を自由に組み合わせられる（取引先・案件ごとに条件がバラバラなため）。

- **人日単価**: 役割ごとに「1人1日あたり ○円」
- **現場固定**: 「1現場1日あたり ○円」
- **成果単価**: 獲得項目ごとに「1件あたり ○円」

請求額（税抜）＝ Σ（人日単価 × 実際に稼働した人数）＋ 現場固定 ＋ Σ（成果単価 × 確定件数）＋（交通費を請求する取引先なら承認済み交通費）

- 当日不稼働・キャンセルの人は人数に含めない。
- 消費税 10%、端数処理は設定で選べる（初期値: 切り捨て）。

#### 支払い（スタッフへ）

- **日当**: スタッフの基本日当。アサインごとに上書き可。
- **インセンティブ**: 獲得項目ごとの全体共通単価（現場ごとに上書き可）× 確定件数。
- **調整額**: ＋ / − の手動調整（理由必須）。
- **交通費・経費**: 承認済みのもの。
- **源泉徴収**: スタッフごとに方式を設定する。
  - なし
  - 報酬・料金: 対象額 × 10.21%（同一月の対象額が100万円を超える部分は 20.42%）
  - 外交員報酬: （月の対象額 − 120,000円）× 10.21%（マイナスなら 0）
  - 対象額に交通費を含めるか、税込・税抜どちらで計算するかは全体設定（初期値は §13 参照）。1円未満切り捨て。
  - 設定画面に「税務上の扱いは税理士に確認のこと」と表示する。
- **差引支払額** ＝ 日当計 ＋ インセンティブ計 ＋ 調整額 ＋ 交通費・経費 − 源泉徴収額
- **支払いサイクル**: 月末締め・翌月末払い。状態は 未確定 → 確定（締め時）→ 支払済（支払日を入力）。
- 支払い一覧にインボイス登録の有無を表示する（freee 側の処理に使う）。

#### 月次締め

- **チェックリスト**: 実績未確定の現場、未承認の経費、未報告のアサインの件数を表示。0件でなくても警告のうえ締められる。
- 締めると、その月の請求額・支払額をスナップショットとして保存し、その月の実績・単価・経費の編集をロックする。ロック解除はオーナーのみ、理由を記録する。

#### 出力（CSV、Excel で文字化けしない UTF-8 BOM 付き）

- 取引先別の請求集計（現場ごとの明細付き）
- スタッフ別の支払明細（日当・インセンティブ・調整・交通費経費・源泉・差引、現場ごとの明細付き）
- **freee 取込用CSV**（freee の「取引のインポート」形式）。列の並びや勘定科目は設定ファイルで変えられるようにする。実装前に freee の最新ヘルプを確認するか、ユーザーにサンプルをもらう。
- （任意）全銀フォーマットの総合振込データ。使っている銀行をユーザーに確認してから作る。

#### 数字の見える化

- 今月の売上・支払・粗利（確定分と見込み分を分けて表示）、直近12か月の推移、取引先別・会場別の売上と粗利、月次目標との比較。
- **見込みの計算**: 実績未確定の現場は「確定人数 × 人日単価 ＋ 現場固定 ＋ 速報件数 × 成果単価」（速報がなければ成果分は 0）。
- **粗利** ＝ 請求額（税抜）− 報酬支払額（税抜換算）− 請求しない交通費・経費

### 4.10 会場

- 一覧・詳細: 名前、住所（地図リンク）、最寄り駅、エリア、主な取引先、入館方法・控室・駐車場などのメモ、過去の現場と獲得実績。

### 4.11 横断検索

- 画面上部の検索窓から、スタッフ・会社・担当者・会場・現場をまとめて検索。ひらがな / カタカナ、電話番号のハイフン有無を吸収する。

### 4.12 文面テンプレート

- 種類: 打診 / 確定連絡 / 前日リマインド / 稼働可能日の提出依頼（全体向け・個別リマインド）/ 実績報告のお願い
- 差し込み: `{名前}` `{日付}` `{曜日}` `{時間}` `{集合時刻}` `{集合場所}` `{会場名}` `{住所}` `{役割}` `{持ち物}` `{マイページURL}` `{締切日}`
- 設定画面で編集でき、プレビューを表示する。初期文面は丁寧すぎない現場向けの文体で用意する。

### 4.13 データ取り込み

- **対象**: スタッフ名簿・取引先・会場（Phase 1）／過去の稼働・実績（Phase 2）
- **手順**: CSVアップロード → 列の対応づけ → プレビュー（エラーと重複候補を表示）→ 実行 → 結果レポート
- **実装前に**、ユーザーから実際のスプレッドシート（CSV。個人情報はダミー化してよい）の先頭数行をもらい、それに合わせる。
- **重複判定**: スタッフは電話番号、会社は名前（「株式会社」「(株)」などの表記ゆれを吸収）。
- 取り込みはオーナーのみ実行できる（日当などの金額項目を含むため）。

### 4.14 設定（オーナーのみ）

ユーザー招待・無効化 / 役割 / 獲得項目 / ランク（S・A・B・C と定義メモ）/ エリア / インセンティブ標準単価 / 税・源泉・端数の設定 / 稼働可能日の締切日 / 月次目標（売上・粗利）/ 文面テンプレート / 会社情報

### 4.15 変更履歴（監査ログ）

- 金額・実績・アサインの状態・営業ステータスの変更は「誰が・いつ・何を・何から何に」変えたかを記録。オーナーが閲覧できる。

## 6. 非機能要件

## 9. UI / UX の原則（迷ったらこれで決める）

1. **毎日やる操作は3タップ以内**（打診、確定、実績報告、活動記録）。
2. **必須項目は最小限**。それ以外は「詳細」に折りたたむ。
3. 件数は ＋ / − ボタン（数字キーボード入力も可）。日付は「今日 / 明日 / 来週」などワンタップ候補を出す。
4. 画面の言葉は現場の言葉（§2）。英語やシステム用語を出さない。
5. **色で状態が分かる**: 赤 = 要対応（欠員・期限切れ・未報告）、黄 = 待ち（打診中・未提出）、緑 = 完了。
6. 空の画面には「次に何をすればいいか」を表示する。
7. **基本は削除しない**（無効化 / アーカイブ）。元に戻せる操作は確認ダイアログを出さず「元に戻す」を表示する。
8. 一覧は最初から実用的な並び（直近・要対応が上）。
9. 文字は16px以上（スマホでの自動ズーム防止）、タップ領域は44px以上。
10. 見た目は白ベースのシンプルなUI。アクセントカラーは NICOLY のブランドカラー（Phase 0 でユーザーに確認）。

## 11. 開発ルール（Phase 0 で `CLAUDE.md` に保存する）

- UI はすべて日本語。用語は §2 にそろえる。
- **お金の計算は1か所（例: `lib/money`）にまとめ、すべてテストを書く**。金額は整数（円）で扱い、浮動小数を使わない（例: 10.21% は `floor(額 × 1021 / 10000)`）。
- **日付処理は1か所（例: `lib/date`）にまとめ、日本時間固定**。
- DB の変更と RLS ポリシーはマイグレーションファイルで管理する。

- ダミーデータ（seed）: スタッフ40人、取引先8社、協力会社10社、会場25か所、2か月分の現場100件程度と実績。実在の人名・電話番号は使わない。
- 各フェーズの終わりに、①テスト全件通過 ②ユーザーが自分で確認する手順 ③未対応・既知の問題の一覧 を出す。

## 13. 仮置きの前提（Phase 0 でユーザーに確認する）

11. インセンティブ単価は全体共通（現場ごとに上書き可）。スタッフ個人ごとの差はつけない。
